# โครงสร้างระบบคั่นไว้

เว็บจัดชั้นหนังสือส่วนตัวและเช็กก่อนซื้อ ใช้ HTML/CSS/JavaScript กับ Node.js และ SQLite เว็บกับ API มาจากเซิร์ฟเวอร์เดียวกัน แต่ละบัญชีมีชั้นหนังสือของตัวเอง เปิดได้ข้ามเครื่อง และใช้ข้อมูลที่โหลดไว้ผ่าน PWA ได้

```text
มือถือ / คอม
  ├─ หน้าเว็บและ PWA
  ├─ IndexedDB เก็บสำเนาชั้นและคิวรอส่ง
  └─ JSON API → Node.js → SQLite + ไฟล์รูปปก
                       └→ แหล่งข้อมูล ISBN เมื่อสั่งค้น
```

## โค้ดอยู่ตรงไหน

| ส่วน | หน้าที่ |
| --- | --- |
| [public/](../public) | หน้าเว็บและไฟล์ PWA โดย `app.js` ประสานการค้น กรอง เพิ่มหนังสือ และเปิดหน้ารายละเอียด ส่วน `shelf-view.js` กับ `detail-view.js` รับผิดชอบการแสดงผล |
| [public/account-store.js](../public/account-store.js) | จัดการบัญชี สำเนาข้อมูลออฟไลน์ คิวงาน และการซิงก์เมื่อกลับมาออนไลน์ |
| [public/lib.js](../public/lib.js) และ [sync-core.js](../public/sync-core.js) | กฎข้อมูลที่เว็บและเซิร์ฟเวอร์ใช้ร่วมกัน เช่น ตรวจ ISBN ตรวจโครงสร้างชั้น และหาว่ารายการไหนเปลี่ยน |
| [server.mjs](../server.mjs) | เสิร์ฟหน้าเว็บ รับคำขอ API และตรวจ session ก่อนเข้าถึงข้อมูลส่วนตัว |
| [src/](../src) | `storage.mjs` จัดการ SQLite รูปและข้อมูลสำรอง, `auth.mjs` ดูแลรหัสผ่านและ session, `isbn.mjs` ติดต่อแหล่ง ISBN, `cli.mjs` ใช้สำรองและกู้ข้อมูล |
| [compose.yaml](../compose.yaml) และ [Dockerfile](../Dockerfile) | รันแอพใน container เดียวและเก็บข้อมูลถาวรใน volume |
| [tests/](../tests) | ตรวจตรรกะข้อมูล API ฐานข้อมูล และการใช้งานผ่านเบราว์เซอร์ |

## หนังสือหนึ่งเรื่องเก็บอย่างไร

- **ฉบับ (`series`)** เก็บชื่อเรื่อง ผู้เขียน หมวด ภาษา และรูปแบบ หนังสือเล่มกับ ebook เป็นคนละฉบับ ผู้ใช้เชื่อมเองด้วย `groupId` เพื่อให้หน้าชั้นแสดงการ์ดเดียวและเปิดรายการเล่มทั้งสองแบบในหน้าเดียว แต่ละแถวแสดงรูปแบบของฉบับนั้น
- **รายการเล่ม (`entry`)** เป็นเล่มเดี่ยวหรือบ็อกซ์ เก็บเลขเล่ม ISBN ถ้ามี จำนวนสำเนา สถานะการครอบครอง และสถานะการอ่าน บ็อกซ์เก็บเลขสมาชิกและสถานะการอ่านรายสมาชิกได้
- **เลขอ้างอิง (`series.target`)** คือเลขเล่มที่ผู้ใช้ระบุ เช่น ออกแล้ว 1–10 ถ้ามี 1–6 เลข 7–10 แสดงเป็นเส้นประ การระบุเลขอ้างอิงไม่สร้างรายการครอบครองหรืออยากซื้อ
- **ถาดรอตรวจ (`draft`)** เก็บข้อมูลก่อนยืนยันเข้าชั้น ส่วนถังขยะใช้ `trashedAt` บนข้อมูลเดิมเพื่อกู้รายการและ ID เดิมได้ หมวดหมู่และการตั้งค่าแหล่ง ISBN แยกตามบัญชี

ยอดผลกรองนับเลขเล่มไม่ซ้ำ **ภายในฉบับ** เช่น บ็อกซ์กระดาษ 1–3 กับกระดาษเล่ม 2 แยก และ ebook เล่ม 2 รวม 4 เล่ม ยอด «มีแล้ว» บนหัวหน้าชั้นนับตามจำนวนสำเนาที่มี จึงอาจต่างจากยอดผลกรอง

## ข้อมูลอยู่ที่ไหน

| ที่เก็บ | ข้อมูล |
| --- | --- |
| `/data/library.sqlite` | บัญชี แฮชรหัสผ่านและ session รายการหนังสือ หมวด การตั้งค่า และข้อมูลสำหรับซิงก์ SQLite schema v3 เก็บ JSON แยกแถวตามฉบับและรายการ |
| `/data/photos/` | ไฟล์ปกแยกตามเจ้าของ ฐานข้อมูลเก็บข้อมูลกำกับและเส้นทางอ้างอิง รูปอ่านผ่าน API ที่ตรวจบัญชี |
| IndexedDB | สำเนาชั้นของบัญชีในเบราว์เซอร์ รวมงานที่รอส่งและเวอร์ชันข้อมูล |
| Cache Storage | ไฟล์แอพและรูปของบัญชีที่เคยโหลดสำหรับเปิดตอนออฟไลน์ |

ไฟล์ JSON ที่ส่งออกใช้ย้ายชั้นหนังสือและรูปปก ส่วนการสำรองทั้งเซิร์ฟเวอร์ใช้ SQLite พร้อมไฟล์รูปและข้อมูลบัญชี ขั้นตอนสำรอง กู้คืน และตั้ง HTTPS อยู่ใน [คู่มือ Docker](deployment.md)

## กดเพิ่มหรือแก้แล้วเกิดอะไรขึ้น

1. กรอกเองหรือค้น ISBN จาก Google Books, Open Library หรือหอสมุดแห่งชาติแบบทดลอง แล้วตรวจข้อมูลก่อนเพิ่มเข้าชั้น รูปบาร์โค้ดใช้ถอดเลขในเครื่อง
2. เว็บบันทึกข้อมูลและงานรอส่งลง IndexedDB แล้วส่งรายการที่เปลี่ยนผ่าน `POST /api/sync`
3. เซิร์ฟเวอร์ตรวจบัญชีและเวอร์ชันของรายการก่อนบันทึก SQLite ถ้าสองเครื่องแก้ข้อมูลเดียวกัน ระบบให้ผู้ใช้เลือกว่าจะเก็บข้อมูลฝั่งไหน
4. เมื่อเซิร์ฟเวอร์ยืนยัน เว็บอัปเดตสถานะบันทึกสำเร็จ เครื่องอื่นดึงข้อมูลล่าสุดจากเซิร์ฟเวอร์ งานที่ยังออฟไลน์จะรอส่งเมื่อเชื่อมต่อได้
