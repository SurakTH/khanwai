# วางรูปปกจากคลิปบอร์ด — 0.10.1

ตั้งแต่ 0.10.2 ส่วนรูปปกในเพิ่ม/ตรวจหนังสือทีละเล่มอยู่หลังข้อมูลหนังสือ และช่องวางรูปพับไว้ก่อนเพื่อลดพื้นที่ ปุ่มวางรูปยังใช้ได้ทันที

ใช้ได้ในเพิ่มหนังสือทีละเล่ม ตรวจรายการรอตรวจ เพิ่มหลายเล่ม และเปลี่ยนปกของฉบับหรือรายเล่ม

1. คัดลอกภาพ เช่น ใช้ **คัดลอกรูปภาพ** จากเบราว์เซอร์ หรือคัดลอกภาพหน้าจอ
2. ในส่วนรูปปก กด **วางรูป** หรือเปิด **วางด้วยคีย์บอร์ด / แตะค้าง** แล้วคลิกช่องวางรูปและกด **⌘V / Ctrl+V** บนมือถือให้แตะค้างในช่องเพื่อเลือกวาง เมื่อเบราว์เซอร์รองรับ
3. ตรวจภาพพรีวิว แล้วกดยืนยันเพิ่มหนังสือหรือบันทึกรูปปกตามปกติ การวางอย่างเดียวไม่ส่งรูปเข้าบัญชีทันที

การเพิ่มหลายเล่มให้เปิด **แนบรูปปกสำหรับแสดงชุดนี้** ก่อนวาง รูปนั้นเป็นปกแทนชุด ไม่ใช่การกำหนดปกเดียวให้ทุกรายเล่ม

ปุ่มอ่านคลิปบอร์ดต้องใช้ HTTPS หรือ localhost และเบราว์เซอร์อาจมีเมนูยืนยัน/ขออนุญาตวาง หากใช้ไม่ได้ ให้ใช้ช่องวางรูปหรือปุ่มเลือกรูป/ถ่ายรูปเดิม HTTP LAN ยังมีทางเลือกรูปเสมอ ไม่รับประกันว่าแต่ละแอพบนมือถือจะส่งไฟล์ภาพมาในคลิปบอร์ดเหมือนกัน ต้องลอง Safari/iPhone และ Android จริงด้วย

ถ้าคัดลอกแค่ลิงก์หรือ HTML ที่อ้างภาพ จะไม่ดาวน์โหลดรูปจาก URL ให้อัตโนมัติ ให้ใช้คัดลอกรูปภาพหรือดาวน์โหลดแล้วเลือกไฟล์ ปกเดิมไม่ถูกล้างเมื่อรูปใหม่อ่านไม่ได้ คลิปบอร์ดว่าง หรือไม่ได้รับอนุญาต

## สำหรับพัฒนาต่อ

- `public/photos.js` เป็น editor ร่วมทุก flow ใช้ `ClipboardEvent.clipboardData` สำหรับ paste ในบริเวณรูป และ `navigator.clipboard.read()` เฉพาะเมื่อกดปุ่ม ไม่อ่านคลิปบอร์ดอัตโนมัติหรือดัก paste ของช่องชื่อเรื่อง/ผู้เขียน/ISBN
- ช่องวางเป็น textarea ขนาด 16px สำหรับมือถือ ไม่ใส่ HTML จากคลิปบอร์ดลง DOM และไม่ดึงภาพจาก URL ภายนอก
- File picker / กล้อง / paste ผ่านตัวเตรียมรูปเดียวกัน: JPG/PNG/WebP, สูงสุด 12 MB และ 40 ล้านพิกเซล ย่อด้านยาวไม่เกิน 720px เป็น JPEG ไม่เกิน 450,000 ตัวอักษร เหมือนเดิม
- generation guard และการตรวจว่า editor ยังอยู่/เปิดอยู่ ป้องกันผลอ่านรูปเก่ากลับมาหลังลบรูป ปิด modal หรือเปลี่ยน flow ไม่เพิ่ม listener ระดับ document ที่ค้างข้าม editor
- getPhoto ยังบล็อกการบันทึกระหว่างเตรียมรูป รูปใช้ owner-scoped storage, outbox และรีวิวเดิม ไม่มี schema/dependency/API route ใหม่ shell-v31 รวม assets ที่แก้แล้ว

ตรวจด้วย `tests/browser/photo-paste.spec.js`: native Chromium clipboard write→keyboard paste→button read, draft/reload, offline paste/reload/sync รูปเข้าบัญชี, batch/series/entry, permission/capability fallback, non-image paste, รูปเก่าไม่หาย, async cancellation และ 320px geometry ใช้ภาพ icon สมมติและบัญชี/ฐานทดสอบแยกจากผู้ใช้ การทดสอบ mobile เป็น emulation จึงไม่อ้างว่าแทนการลองเมนู paste บนมือถือจริงแล้ว
