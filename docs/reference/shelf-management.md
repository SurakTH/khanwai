# ชั้นหนังสือและการนำเข้า CSV — 0.6.0

ผู้ใช้อนุมัติให้ทำข้อเสนอทั้ง 5 ข้อจากการสำรวจ Libib/LibraryThing/CLZ: สลับปกและรายการย่อ, กรองชุดที่ยังเก็บไม่ครบ, แก้หลายรายการ, กรองที่เก็บและแท็กส่วนตัว, นำเข้า CSV พร้อมตรวจทาน รายการนี้เป็น implementation ในเว็บเดิม ไม่ใช่ต้นแบบในแชต

## หน้าชั้น

- ปก / รายการย่อ ใช้ข้อมูลชุดเดียวกันและเรียง/ค้น/กรองเดิมได้ จำมุมมองแยกบัญชีในเบราว์เซอร์นั้น ไม่ซิงก์ preference ข้ามเครื่อง
- รายการย่อแสดงปกเล็ก ชื่อ ฉบับ รูปแบบ สถานะ เล่มที่มี รอส่ง ช่องว่างตามเป้าหมาย และที่เก็บ/แพลตฟอร์ม กดรายการเพื่อเปิดรายละเอียด
- ตัวกรองเพิ่มเติมกางได้: ชุดยังเก็บไม่ครบ / ไม่มีปก / ยังไม่ระบุที่เก็บ รวมกับที่เก็บและแท็กแบบ AND
- ชุดยังเก็บไม่ครบ = มีเลขเป้าหมายอย่างน้อยหนึ่งเล่มที่ยังไม่ owned; เล่ม ordered ยังถือว่ารอรับให้ครบ แต่ไม่อยู่ในรายการ “ยังไม่ได้ซื้อ” บ็อกซ์รวมตามสมาชิกและไม่เพิ่มจำนวนซ้ำ
- ชุดไม่กำหนด target ไม่อนุมานเล่มล่าสุดหรือความครบ ตั้งหรือแก้ target ได้ในแก้ไขข้อมูลเรื่อง เช่น 1-10, ภาคพิเศษ ไม่ดึงวันวางขายเอง
- หน้าเช็กก่อนซื้อยังค้นทุกสถานะ/รูปแบบ ไม่ใช้ตัวกรองจัดชั้นมาซ่อนการซื้อซ้ำ

## แท็กและที่เก็บ

- series.tags เป็น optional string[] ไม่เกิน 30 แท็ก แท็กละไม่เกิน 50 ตัวอักษร ตรวจที่ client และ server อยู่ใน JSON record เดิม ไม่เพิ่ม schema SQLite
- ใช้แท็กระดับเรื่อง/ฉบับ ไม่ติดแท็กเล่มหนึ่งแล้วอ้างว่าแท็กเฉพาะเล่ม กรอกตอนเพิ่มเดี่ยว/หลายเล่ม เก็บ draft แก้ข้อมูลเรื่อง หรือใช้แก้หลายรายการได้
- ที่เก็บอยู่ใน entry.location ตามเดิม แยกแต่ละเล่ม/บ็อกซ์ได้ ebook ใช้เป็นแพลตฟอร์ม ทั้งแท็กและที่เก็บค้นด้วยช่องค้นหาได้
- คั่นแท็กด้วยจุลภาค เซมิโคลอน | หรือขึ้นบรรทัดใหม่ trim/NFC และไม่เพิ่มซ้ำแบบตัวเล็กใหญ่ในการกรอก UI
- tags กับ target ผ่าน sync/outbox/conflict/export JSON และ SQLite backup ต่อเจ้าของเหมือนข้อมูลชั้นเดิม ไม่อยู่ใน public metadata cache

## แก้หลายรายการ

1. กดเลือกหลายรายการ → เลือกเรื่อง/ฉบับ → ตรวจและแก้รายการที่เลือก
2. เลือกเล่มหรือบ็อกซ์แต่ละรายการในฟอร์ม ค่าเริ่มต้นเลือกเฉพาะเล่มที่ตรงตัวกรองสถานะและที่เก็บปัจจุบัน มีเลือกทั้งหมดและล้างที่เลือก
3. เลือกสถานะใหม่หรือคงเดิม เปลี่ยนที่เก็บหรือล้าง และเพิ่ม/ลบ/แทนที่แท็ก
4. ตรวจชื่อเรื่อง รูปแบบ เลขเล่ม ค่าเดิม → ค่าใหม่ และแท็กของฉบับ ก่อนยืนยัน ยกเลิกแล้วไม่มี mutation

สถานะและที่เก็บแก้เฉพาะ entry ที่ติ๊ก แท็กกระทบทั้งฉบับที่มี entry ถูกเลือกและมีข้อความกำกับชัด ไม่แก้ ISBN จำนวนสำเนา สมาชิกบ็อกซ์ หรือสร้างเล่มใหม่ Selection ไม่เก็บข้ามบัญชี/refresh และเลือกข้ามตัวกรองไม่ได้ (รายการที่ถูกซ่อนจะหลุดจาก selection)

ทุก confirmation ใช้ mutation เดียวพร้อม revision bases ของตอนเริ่มตรวจ หาก offline อยู่ใน outbox โดยไม่แสดงว่าซิงก์แล้ว หากชนกันใช้ conflict UI เดิม ไม่ทับค่าของอีกเครื่องเงียบ ๆ

## CSV

เข้า ข้อมูลและการตั้งค่า → สำรองและนำเข้าข้อมูล → นำเข้าจาก CSV มีไฟล์ตัวอย่างดาวน์โหลด ใช้ CSV UTF-8 (Excel เลือก CSV UTF-8) ไม่ใช่ไฟล์ .xlsx อ่านในเครื่องและไม่เรียก ISBN/AI จากเนื้อหาไฟล์

- จำกัด 2 MB / 1,000 records / 100 columns มี header ที่ไม่ว่างและไม่ซ้ำ รองรับ BOM, comma, semicolon, tab, CRLF/LF, quoted commas/newlines และ escaped double quotes ตาม RFC 4180 ตัวคั่นต้องเลือกก่อนเปิดไฟล์
- หนึ่ง record ต่อ volume หรือ box ไม่ใช้หนึ่ง ISBN เติมหลายเล่ม ไม่อ่าน owner/ID/รูป URL จาก CSV
- จับคู่คอลัมน์ด้วย index แนะนำจาก header ไทย/อังกฤษ แล้วผู้ใช้เปลี่ยนได้ แสดงตัวอย่างค่าคอลัมน์ ห้ามใช้คอลัมน์เดียวแทนหลาย field
- เมื่อไม่จับคู่ ใช้ค่าที่ผู้ใช้ตรวจในฟอร์ม: format เริ่ม physical, status owned, category การ์ตูน, label 1; ฉบับและภาษาไม่เดาจากชื่อ ถ้าขาดต้องกรอกก่อนยืนยัน จำนวนว่าง = 1, kind ว่าง = volume
- รับ format physical/ebook หรือ label ไทยของแอพ, status owned/ordered/wishlist หรือ label ไทย ชื่อเรื่อง ฉบับ ภาษา เลขเล่มจำเป็น ISBN ว่างได้ ตรวจ checksum ถ้ามี
- แท็กและ target/member ใช้รูปแบบคั่นรายการเดียวกับด้านบน box ต้องระบุ kind=box และสมาชิกชัดเจน เพื่อไม่อ้าง coverage ผิด
- ตรวจทานทุก record แสดงพร้อมเพิ่ม/ซ้ำ/ต้องแก้/เว้นไว้ ติ๊กเว้นได้ เปิดดูและแก้ทุก field แล้วตรวจใหม่ก่อนยืนยัน แก้ข้อมูลแล้วปุ่มยืนยันถูกปิดจนตรวจใหม่ แถวที่ยังผิดต้องแก้หรือติ๊กเว้นก่อนยืนยัน
- duplicate ข้ามโดยไม่เพิ่มอีกสำเนา: ISBN canonical 10/13 เดียวกันใน format เดียว หรือเลขเล่มทับรายการ/สมาชิกบ็อกซ์ของฉบับนั้น รวมการซ้ำภายในไฟล์ ไม่เปลี่ยนสถานะของเล่มเดิมเพื่อรับไฟล์
- จับคู่ฉบับเฉพาะ title+author+edition+language+format ตรงกันหลัง trim/NFC/casefold หากฉบับเดิมซ้ำหลาย ID ให้แยกข้อมูลก่อน ไม่ fuzzy merge หาก target ต่างกันให้แก้หรือเว้นไว้
- แถวที่เพิ่มใหม่อาจรวม tags และตั้ง target ให้ฉบับเดิมที่ยังไม่กำหนด แต่ไม่แก้ชื่อ/ภาษา/ฉบับหรือ target เดิมที่ขัดกันจากไฟล์
- ตรวจซ้ำกับ snapshot ปัจจุบันตอนยืนยัน หากผลเปลี่ยนต้องตรวจใหม่ ไฟล์เดิมยังไม่ทำ ownership จนยืนยัน ใช้ outbox เดิมและ retry operation ID เดิมเมื่อเน็ตหลุด

CSV เป็นช่องนำเข้าข้อมูล ไม่ใช่ backup รูปหรือการตั้งค่า สำรองแบบเต็มใช้ JSON/SQLite+photos เดิม ยังไม่มี CSV export ในรอบนี้
