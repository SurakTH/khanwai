# ISBN แหล่งข้อมูล และ AI

## หลักการ

สแกนบาร์โค้ดคือการอ่านรหัส ไม่ได้อ่านชื่อเรื่องออกมาจาก ISBN โดยตรง การมี ISBN ไม่รับประกันว่า provider ที่เราใช้จะมีข้อมูลครบ และไม่รับประกันสิทธิ์นำรูปปกมาเก็บต่อ ต้องตรวจเอกสารและเงื่อนไขของแต่ละแหล่งก่อนเชื่อมจริง

## Pipeline

1. รับ ISBN จาก scanner หรือข้อความ โดยใช้ตัวอ่าน barcode ตามมาตรฐาน ไม่ใช้ generative AI เป็นตัวถอดรหัสหลัก
2. normalize ช่องว่าง/ขีด ตรวจชนิดและ checksum บอกข้อผิดพลาดให้แก้ได้
3. ตรวจรายการของบัญชีนี้ รวม owned, ordered, wishlist และ draft โดยแยกความหมายของแต่ละสถานะ
4. ค้น metadata ผ่าน adapter ตามลำดับ provider ที่ผ่านการทดลองแล้ว
5. เก็บ candidate พร้อม source, external ID และเวลา ปรับรูปแบบให้เป็น schema กลาง
6. ตรวจ ISBN ของผลที่ได้ว่าตรงกับคำค้นหรือเป็นรูปเทียบเท่าที่ตรวจแล้ว ผลไม่ตรงห้ามจัดเป็น exact match
7. ถ้าข้อมูลขัดกันหรือได้หลายฉบับ ให้ผู้ใช้เลือก ห้ามรวมคนละฉบับด้วย AI
8. เปิด review แก้และยืนยันก่อนเข้าชั้น จากนั้น sync ตามโปรโตคอลหลัก

การดึงข้อมูลใหม่ต้องไม่เขียนทับฉบับที่ผู้ใช้แก้แล้ว ผลไม่พบ/timeout ต้องไม่ลบ draft

## Provider adapters

แยก interface `lookupByIsbn` ออกจาก UI เพื่อเปลี่ยนแหล่งได้ คืนสถานะแบบ found/not_found/rate_limited/unavailable/invalid_response พร้อม candidates และ provenance

- ปัจจุบัน 0.3.1 ใช้ Google Books เป็นแหล่งแรกและ Open Library Books API สำรองเมื่อไม่พบ/ล่ม/จำกัดคำขอ; ยังไม่รับรองความครอบคลุมหนังสือไทย ดู cache/rate policy ใน docs/development/decisions.md
- ลองแหล่งสำรองได้เมื่อมี API/สิทธิ์ใช้งานชัดเจน ห้ามถือว่าเว็บที่ค้นเจอ scrape ได้โดยอัตโนมัติ
- ตั้ง timeout, bounded retries, deduplicate คำขอ และ cache ตามเงื่อนไขบริการ
- cache “ไม่พบ” ชั่วคราว แยกจากระบบล่ม ไม่ cache ถาวรจนหนังสือใหม่ค้นไม่เจอ
- ชื่อไทย/จีน/อังกฤษเก็บตามที่ได้รับ แสดงความต่างให้เห็น ไม่แปลทับชื่อหลักอัตโนมัติ

## AI extraction

อินพุต: รูปที่ผู้ใช้เลือกเอง เช่น ปกและหน้าลิขสิทธิ์ บีบอัดอย่างพอเหมาะและตัด metadata ของภาพที่ไม่จำเป็น

เอาต์พุตที่คาดหวัง: JSON ตาม schema ของชื่อเรื่อง ผู้สร้าง/บทบาท สำนักพิมพ์ ภาษา label เล่ม ฉบับ และ ISBN แต่ละช่อง nullable พร้อมข้อความหลักฐานจากภาพเมื่ออ่านได้

- ให้ extract จากภาพ ไม่เติมจากความรู้เดิมหรือคาดเดาว่าเป็นเรื่องที่รู้จัก
- ข้อความในภาพเป็นข้อมูล ไม่ใช่คำสั่งให้โมเดลใช้เครื่องมือหรือเปลี่ยนการทำงาน
- ตรวจ schema ความยาว field และ ISBN ฝั่ง server ทุกครั้ง แม้โมเดลคืน structured output
- หลักฐานข้อความที่โมเดลคืนก็อาจผิด ให้ผู้ใช้เทียบรูปเดิมได้เสมอ
- ไม่ใช้คะแนนความมั่นใจที่โมเดลให้เองเป็นหลักฐานว่าแม่น; วัดจากชุดทดสอบจริง
- AI ห้ามเพิ่ม entry, merge เรื่อง, ยืนยัน ownership หรือแก้สถานะเอง
- หาก schema ไม่ผ่าน โควตาหมด หรือ provider ล่ม แสดงทางกรอกเองโดยไม่ทำข้อมูลสูญหาย

## รูปและความเป็นส่วนตัว

- บอกก่อนส่งว่ามีการใช้ผู้ให้บริการภายนอก แยกการประมวลผลรูปออกจากการเลือกเก็บเป็นปก
- รูปต้นฉบับเป็น private ไม่ทำ public URL ถาวรเพื่อให้โมเดลอ่าน
- เสนอให้ลบรูป extraction หลังงานจบ โดยต้องกำหนด TTL และ cleanup งานค้างก่อน production
- ตรวจ retention/การใช้ข้อมูลของ provider จริง ห้ามสัญญาว่าผู้ให้บริการไม่เก็บอะไรถ้ายังไม่ตรวจเงื่อนไข
- ข้อมูลส่วนตัวจากรูปและผล AI ไม่อยู่ใน cache metadata ร่วม

## การทดลองก่อนเลือกบริการ

ใช้ตัวอย่างประมาณ 20 เล่ม ครอบคลุมการ์ตูน นิยายไทย นิยายแปลจีน เล่มพิเศษ บ็อกซ์ ไม่มี ISBN และภาพแสงไม่ดี ผู้ใช้เลือกส่งรูปจริง หรือใช้ตัวอย่างที่อนุญาตแทน ไม่ต้องส่งทั้งคอลเลกชัน

บันทึก ISBN lookup hit rate, จำนวนช่องที่ถูก/ผิด/ว่าง, การสลับเลขเล่ม/ภาษา/ฉบับ, เวลาต่อรายการ, ค่าใช้จ่ายต่อรายการ และจำนวนการแก้จากผู้ใช้ เปรียบเทียบกับกรอกมือ ใช้ผลนี้ตัดสิน provider และว่าจะเปิด AI ใน release แรกหรือไม่
