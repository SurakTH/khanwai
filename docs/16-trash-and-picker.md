# สุ่มเรื่องที่ยังไม่อ่าน และถังขยะ — 0.10.0

## สุ่มอ่าน

ชั้นหนังสือ → **••• → สุ่มเรื่องที่ยังไม่อ่าน**

เลือกจากฉบับที่มีอย่างน้อยหนึ่งเล่ม `owned` และมีสถานะ `unread` รวมค่าเริ่มต้นที่ยังไม่ได้เลือกการอ่าน ใช้คำค้น หมวด รูปแบบ ที่เก็บ แท็ก และตัวกรองชุดเดิม แต่เปลี่ยนแท็บเป็นมีแล้วและตัวกรองการอ่านเป็นยังไม่อ่าน ไม่รวมรอส่ง อยากซื้อ อยากอ่าน กำลังอ่าน อ่านแล้ว หรือรายการในถังขยะ

แต่ละเรื่อง/ฉบับมีหนึ่งสิทธิ์ ไม่ถ่วงน้ำหนักด้วยจำนวนเล่มหรือสำเนา ถ้ามีหลายเรื่อง ปุ่มสุ่มอีกเรื่องจะไม่เลือกเรื่องที่เพิ่งแสดงทันที บ็อกซ์อ่านจาก `readingByMember` ตามปกติ หากสำเนาอื่นของเลขเล่มเดียวกันอ่านแล้ว จะไม่เสนอเลขนั้นเป็นยังไม่อ่าน การกรองที่เก็บไม่ลบประวัติว่าอ่านสำเนาอื่นแล้ว

ผลแสดงปก ชื่อ ฉบับ และเลขเล่มที่ยังไม่อ่าน พร้อมเปิดรายละเอียด การสุ่มไม่แก้ข้อมูลหรือสถานะการอ่าน ถ้าไม่มีตัวเลือกตรงเงื่อนไขจะแจ้งผลว่างและให้เลือกกลับ/ล้างตัวกรอง

## ถังขยะ

ชั้น → **••• → ถังขยะ / กู้คืน** หรือ **ตั้งค่า → ถังขยะและกู้คืน**

- ลบรายเล่มหรือรายการรอตรวจจะย้ายไปถังขยะหลังยืนยัน
- ในรายละเอียดฉบับมีปุ่ม **ย้ายทั้งฉบับไปถังขยะ** สำหรับชุดใหญ่
- ค้นในถังขยะได้ แล้วกด **ตรวจและกู้คืน → ยืนยันกู้คืน** เพื่อคืนรหัสเดิม ข้อมูลฉบับ สถานะการครอบครอง/การอ่าน สำเนา สมาชิกบ็อกซ์ และรูปเดิม
- ถ้าพบ ISBN หรือเลขเล่มที่อาจซ้ำกับข้อมูลปัจจุบัน ต้องติ๊กยืนยันหลังตรวจรายการก่อนกู้คืน ไม่รวมรายการซ้ำเอง
- ถ้าลบรายเล่มก่อน แล้วค่อยย้ายทั้งฉบับ การคืนทั้งฉบับจะไม่คืนเล่มที่ลบแยกไว้ก่อน เล่มนั้นยังอยู่ในถังขยะให้เลือกคืนได้
- กู้คืนได้เฉพาะรายการที่ย้ายเข้าถังขยะตั้งแต่รุ่นนี้ รายการที่ลบจริงก่อนหน้านี้ต้องใช้ไฟล์สำรอง
- เก็บไว้จนกู้คืน ไม่มีหมดอายุหรือลบถาวรอัตโนมัติ รุ่นนี้ไม่มีปุ่มล้างถังขยะหรือลบถาวร ข้อมูลในถังขยะยังใช้พื้นที่และนับรวมขีดจำกัดจำนวน record ของบัญชี
- การลบบัญชียังคงเป็นการลบข้อมูลทั้งบัญชีตาม flow เดิม ส่วนการนำเข้าแบบแทนที่ทั้งชั้นแทนที่ถังขยะด้วยข้อมูลในไฟล์ตามการยืนยัน

ถังขยะไม่ถูกนับในชั้น เช็กก่อนซื้อ จำนวนเล่ม ตัวกรอง หรือการสุ่ม แต่รวมใน JSON export/import และ SQLite backup/restore พร้อมรูป ใช้ออฟไลน์หลังโหลดแอพได้ แสดงรอซิงก์ตามจริง เมื่อแก้ชนจากอีกเครื่องยังต้องเลือกข้อมูลก่อน ไม่เขียนทับเงียบ ๆ หน้าความขัดแย้งแสดงว่ารายการอยู่ในชั้นหรือถังขยะ

## การพัฒนาต่อ

`public/trash.js` เก็บ `trashedAt` เป็น ISO timestamp บน series/entry/draft เดิม ไม่สร้าง snapshot ซ้ำหรือเปลี่ยน ID จึงใช้ record revision/outbox/owner-scoped photos เดิม ไม่เปลี่ยน SQLite v3 หรือ JSON schemaVersion 2 และไม่เพิ่มบริการ

`activeLibrary` แยกมุมมองใช้งานออกจากข้อมูลเต็มใน AccountStore ทุก mutation ยังเขียนข้อมูลเต็ม การรวมไฟล์นำเข้าและการโหลดตัวอย่างต้องรักษาข้อมูลถังขยะ การเลือก CSV จะข้ามรายการในถังขยะเมื่อตรวจซ้ำ และตอนกู้คืนจะเตือนหากเพิ่มเล่มทดแทนไว้แล้ว การเปลี่ยนการอ่านทั้งฉบับ/bulk ไม่แก้ entry ในถังขยะ

`trash-ui.js`/`trash.css` ดูแลรายการและตรวจคืน `unread-picker.js` คำนวณผู้สมัครโดยไม่แก้ข้อมูล ไม่ใช้ Math.random สร้าง ID; ID ใหม่ยังผ่าน ids.js เสมอ ไม่มีหน้าเมนูหลักเพิ่มหรือ badge ถาดรอตรวจ และคง layout ชั้นแบบ 0.8.6

ควรอัปเดตเว็บ/PWA ทุกเครื่องเป็น 0.10.0 ก่อนแก้ข้อมูลต่อ แอพเก่าไม่รู้ความหมายของ trashedAt และอาจแสดงรายการเหล่านี้ได้ การย้อนกลับ image ควรกู้ backup ก่อนอัปเดตลง directory ว่างตามคู่มือ Docker

ตรวจด้วย trash-picker.test.js, trash-picker.spec.js, backend.test.js, ชุด browser เดิม และ docker-smoke.mjs ภาพ preview ใช้ฐานแยกและเก็บเฉพาะในเครื่อง ไม่รวมข้อมูลส่วนตัวใน repository
