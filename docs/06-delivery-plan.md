## Phase 0 — ลดความไม่แน่นอน

ประวัติ: 0.2.0 เคยมีบัญชีจำลอง ปัจจุบันถอด mockup แล้วและเปลี่ยนเป็น auth จริง ฟีเจอร์เพิ่มชุด/รูปอยู่ในเมนูปกติ ไม่มีแท็บทดลอง

- [x] ระบุอุปกรณ์หลัก iPhone และรองรับ Android/คอม (รุ่น OS และการลองกล้องยังเปิดอยู่)
- [ ] รวบรวมตัวอย่างหนังสือประมาณ 20 เล่มตามความสมัครใจ รวมกรณีพิเศษ
- [x] ทำต้นแบบหน้าค้นหา รายละเอียดชุด และ review บนมือถือกับคอม พร้อม browser tests
- [ ] ทดลองอ่าน barcode จากกล้อง พร้อม fallback เลือกรูป/พิมพ์เลข
- [ ] ทดลองความครอบคลุม ISBN และ AI ตามเอกสาร ingestion
- [x] เลือก stack/auth/storage สำหรับ self-host (ยังไม่เปิด public hosting)
- [x] บันทึกวิธีล็อกอิน นโยบายรูป แหล่งข้อมูล และขอบเขต browser ที่ตรวจแล้วใน decision log/10-implementation

เสร็จเมื่อ: มี prototype หน้าจอ ผลทดลองที่ตรวจได้ และรายการตัดสินใจสำหรับสร้างระบบหลัก ไม่ต้องมี AI integration เต็มรูปแบบเพื่อเริ่มงานส่วนอื่น

หลักฐานปัจจุบัน: `public/`, `src/`, `server.mjs`, `tests/` และภาพใน docs/screenshots; unit/API 22 และ browser 64 tests ผ่านกับ Docker 0.3.0 (รวม 86) พร้อม Docker recreate/SQLite+photo restore แยกอีกหนึ่ง smoke scenario การลอง Google Books สอง ISBN สาธารณะยังได้ rate limit ไม่ใช่ coverage 20 เล่ม ยังไม่มี AI/กล้องฮาร์ดแวร์จริง

ลำดับที่ปรับสำหรับเริ่มใช้: ต้นแบบ -> online slice พร้อมบัญชีและข้อมูลข้ามเครื่อง -> PWA อ่านออฟไลน์ -> offline mutations/conflicts โดยออกแบบ revision/idempotency ใน backend ตั้งแต่ต้น การแบ่งนี้ไม่ตัดข้อกำหนดออฟไลน์เดิม แต่ไม่บังคับรอ offline editing เต็มรูปแบบก่อนให้ลองระบบออนไลน์

## Phase 2 — เพิ่มหนังสือและรีวิว

ขึ้นกับ: ข้อมูลและสิทธิ์ใน Phase 1; barcode/provider spike จาก Phase 0

- [ ] ISBN validation, adapter, provenance และ error states
- [ ] เช็กซ้ำก่อน lookup และก่อน commit กันการเปลี่ยนข้อมูลระหว่างรีวิว
- [ ] review form, ถาดรอตรวจ และสแกนต่อเนื่อง
- [ ] AI extraction เฉพาะเมื่อผลทดลองผ่าน พร้อมโควตาและ fallback

## Phase 3 — PWA และออฟไลน์

ขึ้นกับ: สัญญา API revision/idempotency ที่ต้องออกแบบตั้งแต่ Phase 1 ไม่รอเพิ่มตอนท้าย

- [ ] manifest, icons, HTTPS, install guidance ตามแพลตฟอร์ม
- [x] local DB แยกบัญชี, app cache, outbox และ schema migration
- [x] delta sync, idempotency, conflict UI และ tombstones
- [x] สถานะซิงก์ เซสชันหมดอายุ logout และการสลับบัญชี
- [x] อัปเดตแอพโดยไม่บังคับปิดฟอร์มหรือล้าง outbox (waiting worker และเปิดใหม่ทดสอบแล้ว; schema IndexedDB ยังเป็น version 1)

เสร็จเมื่อ: เคยโหลดแล้วเปิดแอพใหม่แบบไม่มีเน็ต ค้นและแก้ได้ ต่อเน็ตแล้วส่งสำเร็จเพียงครั้งเดียว และจัดการข้อมูลชนกันโดยไม่เขียนทับเงียบ ๆ
