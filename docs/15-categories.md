# หมวดหมู่ของแต่ละบัญชี

ตั้งค่า → หมวดหมู่หนังสือ → **จัดการหมวดหมู่**

- เริ่มด้วย การ์ตูน / นิยายวายไทย / นิยายแปลจีน / อื่น ๆ เหมือนเดิม
- เพิ่มชื่อของตัวเอง เช่น การ์ตูนวาย หมวดที่ยังไม่มีหนังสือก็เก็บไว้ได้
- เปลี่ยนชื่อแล้ว หนังสือและรายการรอตรวจในหมวดนั้นเปลี่ยนตาม
- ลบหมวดที่ใช้อยู่ต้องเลือกหมวดปลายทางก่อน หนังสือ รายการรอตรวจ รูป และสถานะยังอยู่ครบ ต้องเหลืออย่างน้อยหนึ่งหมวด
- ชื่อไม่ว่าง ไม่เกิน 300 ตัวอักษร สูงสุด 100 หมวด ไม่ซ้ำหลังปรับ Unicode/ช่องว่าง/ตัวพิมพ์ และไม่ใช้ชื่อ `all` ซึ่งเป็นค่าตัวกรองทั้งหมด

รายการนี้ใช้ร่วมกันในเพิ่มทีละเล่ม เพิ่มหลายเล่ม ตรวจ draft แก้เรื่อง/ฉบับ ตัวกรองชั้น และ CSV โดยหมวดเป็นข้อมูลระดับเรื่อง/ฉบับ ไม่ใช่รายเล่ม หาก CSV ใช้ชื่อใหม่ ให้เพิ่มหมวดในตั้งค่าก่อน หรือเลือกหมวดที่มีอยู่ระหว่างตรวจข้อมูล

## ข้ามเครื่อง ออฟไลน์ และสำรอง

เก็บแยกบัญชีผ่านคิวซิงก์เดิม ใช้ออฟไลน์ได้หลังโหลดแอพ เมื่อมีงานรอส่งจะไม่อ้างว่าบันทึกบนเซิร์ฟเวอร์แล้ว หากแก้หมวดชนกันสองเครื่องใช้หน้าตรวจความขัดแย้งเดิมที่แสดงรายชื่อหมวดทั้งสองฝั่ง

หมวดรวมใน JSON export แม้ยังไม่มีหนังสือ การนำเข้าแบบรวมเก็บหมวดเดิมและหมวดในไฟล์ ส่วนแทนที่ทั้งชั้นใช้หมวดจากไฟล์ (ไฟล์เก่าที่ไม่มีรายการหมวดจะเริ่มจากค่าเดิมพร้อมชื่อที่หนังสือในไฟล์อ้างถึง) SQLite backup/restore รวมหมวดด้วย

หากอุปกรณ์ที่ออฟไลน์หรือการเลือกแก้ conflict นำชื่อเก่ากลับมาอ้างในหนังสือ ชื่อนั้นจะแสดงในรายการหมวดให้จัดการได้อีกครั้ง ไม่ซ่อนหนังสือหรือเดาว่าต้องย้ายไปไหน เปิดจัดการหมวดแล้วย้ายรวมได้

## โครงสร้างสำหรับพัฒนาต่อ

`public/categories.js` เป็นแหล่งเดียวสำหรับค่าเริ่มต้น การตรวจชื่อ รายการหมวด และคำสั่งเพิ่ม/เปลี่ยนชื่อ/ลบ ส่วน `category-ui.js`/`category-ui.css` ดูแลตั้งค่าและ modal ไม่จัดหน้า shelf ใหม่

`state.categories` เป็น optional string array; ไม่มี field ใช้ค่าเริ่มต้นตอนแสดง ไม่เขียนย้อนหลังเพียงเพราะเปิดแอพ ค่าบน series/draft ยังเป็นชื่อหมวด การเปลี่ยนชื่อ/ย้ายจะบันทึก catalog และ record ที่กระทบใน mutation เดียว พร้อม revision/outbox/conflict เดิม

sync key `catalog:categories` มี `{id:'categories', names:[...]}` SQLite migration v2 → v3 เพิ่มตาราง `catalogs` แยก owner มี revision และ tombstone JSON schemaVersion ยังเป็น 2 และรับ backup เก่าได้ แอพรุ่นเก่าปฏิเสธ DB v3 ดังนั้นก่อนอัปเกรดต้องเก็บ backup; หากย้อน image ให้ restore backup ก่อนอัปเกรดลง directory ว่างตามคู่มือ Docker

ยอมรับชื่อหมวดที่หนังสืออ้างถึงแม้ไม่อยู่ใน catalog เพื่อรองรับข้อมูลจากเครื่องเก่าและ conflict โดย `categoryList` รวมรายการที่ตั้งไว้กับชื่อที่ถูกอ้างถึง ไม่ทิ้งการจัดหมวดเงียบ ๆ ไม่เพิ่ม API หรือบริการภายนอก

ตรวจรับด้วย `tests/categories.test.js`, `tests/browser/categories.spec.js`, ชุด backend/browser เดิม และ `tests/docker-smoke.mjs` สำหรับการอัปเกรดจาก 0.8.6 พร้อมกู้ backup และย้อนผ่าน backup เดิม
