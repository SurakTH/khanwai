# หน้าจอและขั้นตอนใช้งาน

## โครงหน้าจอ

- **เช็กก่อนซื้อ:** หน้าเฉพาะสำหรับตัดสินใจก่อนซื้อ เปิดมารอค้นโดยไม่แสดงชั้นซ้ำ มีชื่อ/ISBN และเลขเล่มแบบไม่บังคับ ผลลัพธ์สรุป owned/ordered/wishlist พร้อมหนังสือเล่ม/ebook และบ็อกซ์ ไม่ใช้ gallery หรือตัวกรองที่ซ่อนข้อมูลสำคัญ สถานะปัจจุบันยังเป็นข้อมูลในเครื่อง ไม่แสดงเวลาซิงก์คลาวด์สมมติ
- **ชั้นหนังสือ:** แสดงเป็นเรื่อง กรองประเภท ภาษา สถานะ และชุดที่ยังไม่ครบ
- **รายละเอียดเรื่อง:** เลือกฉบับ/ภาษา เห็นตารางเลขเล่ม เล่มพิเศษ บ็อกซ์ และสำเนาที่มี
- **เพิ่มหนังสือ:** พิมพ์ ISBN สแกน กรอกเอง เพิ่มช่วงเล่ม หรืออัปโหลดรูปให้ AI ช่วย
- **ถาดรอตรวจ:** รายการที่ดึงข้อมูลแล้ว/กำลังค้น/ค้นไม่เจอ ตรวจและยืนยันทีละรายการหรือหลายรายการ
- **บัญชีและข้อมูล:** เข้าสู่ระบบ การซิงก์ ส่งออก/นำเข้า จัดการข้อมูลและบัญชี

มือถือเน้นการใช้มือเดียวและปุ่มกดชัดเจน คอมใช้พื้นที่สำหรับแก้หลายรายการ ทุกสถานะต้องมีข้อความประกอบสี ใช้คีย์บอร์ดได้และมี label สำหรับตัวอ่านหน้าจอ

## A. เช็กก่อนซื้อ

1. เปิดแล้วพร้อมค้น ไม่บังคับผ่าน dashboard
2. ค้นชื่อ/ชื่อย่อ/ผู้เขียน หรือสแกน ISBN
3. แสดงผลตรงก่อน แล้วแยกผลคล้ายให้เทียบ
4. แสดงว่ามีแล้ว รอส่ง อยู่ในบ็อกซ์ หรืออยู่เฉพาะ wishlist
5. ถ้าไม่พบ ให้เพิ่มเป็น draft หรือกรอกเองได้

หน้าชั้นใช้ดูปกและจัดคอลเลกชัน หน้าเช็กใช้ผลสรุปแยกฉบับ ไม่แสดงหนังสือทั้งหมดก่อนพิมพ์ เมื่อระบุเลขเล่มจะตอบเฉพาะเล่มนั้น เมื่อค้น ISBN ให้ยึดสถานะของ entry ที่ ISBN ตรง ไม่เหมารวมว่ามีแล้วเพราะในเรื่องเดียวกันมีเล่มอื่นอยู่ ถาดรอตรวจแสดงเป็นคำเตือนแยก ไม่รวมใน owned

การสแกนในหน้าเช็กจะค้นในชั้นก่อน ส่วนการสแกนในฟอร์มเพิ่มยังคงดึง metadata เพื่อรีวิว เบราว์เซอร์ที่ไม่มี BarcodeDetector ให้พิมพ์ในหน้าที่กำลังใช้อยู่โดยไม่เด้งไปฟอร์มเพิ่มเอง

กรณีออฟไลน์ต้องบอกว่าเป็นผลจากข้อมูลในเครื่องและซิงก์ล่าสุดเมื่อไร ถ้าไม่เคยโหลดชั้นมาก่อนให้บอกว่ายังเช็กไม่ได้

## B. เพิ่มด้วย ISBN

1. อ่านหรือพิมพ์เลข ปรับรูปแบบและตรวจ checksum
2. ตรวจซ้ำในชั้นและถาดรอตรวจ ถ้าซ้ำแสดงรายการเดิม ไม่ห้ามการซื้อหลายสำเนา
3. ถ้าออนไลน์ เริ่มค้น metadata อัตโนมัติ ถ้าออฟไลน์ เก็บเลขเป็น draft รอค้น
4. หน้ารีวิวแสดงรูป ชื่อ เลขเล่ม ฉบับ ภาษา ผู้เขียน/ผู้แปล สำนักพิมพ์ และแหล่งข้อมูล
5. ผู้ใช้แก้ เชื่อมกับเรื่องเดิมหรือสร้างเรื่องใหม่ เลือกสถานะ แล้วบันทึก
6. แสดงแยกว่าบันทึกในเครื่องแล้ว หรือขึ้นเซิร์ฟเวอร์แล้ว

ISBN ที่ checksum ผ่านไม่ได้ยืนยันว่าเป็นเล่มที่ผู้ใช้ถือ ต้องให้เทียบปกและฉบับด้วย ถ้าสแกนได้รหัสร้านค้าที่ไม่ใช่ ISBN ให้แจ้งและเสนอกรอกชื่อเอง

## C. เพิ่มจากรูปด้วย AI

1. เลือกรูปปกและ/หรือหน้าลิขสิทธิ์ ดู preview ก่อนส่ง
2. แจ้งผู้ให้บริการภายนอกและนโยบายรูปก่อนใช้งานครั้งแรก
3. แสดงข้อเสนอพร้อมช่องที่อ่านไม่ชัด ไม่ซ่อนช่องว่างด้วยการเดา
4. ISBN ที่อ่านได้ผ่าน validation และ lookup แบบเดียวกับ flow B
5. ผู้ใช้ตรวจและบันทึก ความล้มเหลว/โควตาเต็มยังกรอกเองได้

## D. ลงของเก่าจำนวนมาก

- เพิ่มช่วง เช่น 1–12 แล้วติ๊กยกเว้น 8 ได้ โดยไม่สร้าง ISBN สมมติ
- ชื่อเรื่อง/ฉบับใช้ร่วมในชุด แต่สถานะรายเล่มแก้ต่างกันได้
- สแกนต่อเนื่องเข้าถาด พัก/กลับมาทำต่อได้หลัง draft ซิงก์แล้ว
- ยืนยันหลายรายการได้เฉพาะเมื่อเลือกและแสดงข้อมูลที่จะบันทึกชัดเจน ช่องจำเป็นที่ยังไม่ครบต้องแก้ก่อน
- draft ไม่เพิ่มยอด owned แต่ปรากฏเป็นคำเตือนแยกเมื่อค้น/สแกนซ้ำ

## E. บ็อกซ์และสำเนาซ้ำ

เพิ่มบ็อกซ์ -> รีวิวรายการเล่มภายใน -> เลือกสถานะของชุด -> แสดง coverage ที่ได้ ถ้าเล่มภายในยังไม่ทราบให้บอกว่าไม่ทราบ ไม่ถือว่ามีครบทั้งเรื่อง การเพิ่มเล่มเดี่ยวที่อยู่ในบ็อกซ์แล้วต้องเตือนและให้ยืนยันเพิ่มอีกสำเนา

## F. ความขัดแย้งและข้อผิดพลาด

- สองเครื่องแก้ record รุ่นเดียวกัน: แสดงข้อมูลปัจจุบันกับการแก้ที่รอส่ง ให้เลือก/แก้รวมก่อนยืนยันใหม่
- ลบจากอีกเครื่อง: ห้ามคืนชีพอัตโนมัติ ให้เลือกยกเลิกการแก้หรือสร้างรายการใหม่
- API timeout/ไม่พบ/ถูกจำกัด: แสดงแยกสาเหตุ ให้ลองใหม่หรือกรอกเอง
- เซสชันหมดอายุ: เก็บงานที่ยังไม่ส่งไว้สำหรับบัญชีเดิม ไม่ย้ายไปบัญชีที่ล็อกอินใหม่
- ออกจากระบบขณะมีงานรอส่ง: ให้เลือกซิงก์ก่อน หรือยืนยันละทิ้งงานในเครื่อง ห้ามล้างเงียบ ๆ
